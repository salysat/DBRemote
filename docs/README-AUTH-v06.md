# DB Remote v0.6 — Admin session login (local development)

## What changed
- The admin login screen accepts `DBREMOTE_ADMIN_PASSWORD`. Admin tokens are no longer stored in the browser, and the device list uses a server-side cookie session.
- A short-lived one-time viewer ticket is issued by the server for each remote desktop connection. Do not share the internal admin or agent tokens with branches.
- A new admin password is generated by `setup-local.ps1` in `.dbremote-secrets.ps1` without rotating previously generated admin/agent tokens.
- Pending agents still require one-time manual approval; they cannot self-authorize.
- Page refresh and navigation retain the cookie session; sign out with the bottom-left button.

## Start on Windows PowerShell 5.1
1. Stop older servers / agents, and extract into a fresh directory.
2. Preserve your previous `.dbremote-secrets.ps1` and `src/DBRemote.Server/data/devices.json` to retain device registrations. Note that `data/dataprotection` should also be preserved to retain login cookies after app restarts.
3. Run `./setup-local.ps1` in PowerShell. It prints the new admin LOGIN PASSWORD if none existed. The password is in `.dbremote-secrets.ps1`. Do not distribute this file.
4. Run `./start-server.ps1` and visit `http://localhost:5080/dashboard.html`.
5. Sign in once with the generated password; afterwards refreshing devices should work automatically until session expiry or logout.
6. Run an agent from the matching version and approve the device from Devices.

## Important limitations
This is a local-only pilot, NOT an internet-ready remote administration system. It uses a single administrator password, not ASP.NET Core Identity (no user registration, role management, MFA, recovery, or independent account revocation). It has a basic IP-scoped login throttle in memory. Deploy only on loopback while testing. For public deployment, implement ASP.NET Core Identity, MFA, HTTPS with trusted reverse proxy configuration, stronger rate limiting and audit trails, per-device credentials, and security review.

On the first upgrade, when an old `.dbremote-secrets.ps1` exists, run `./setup-local.ps1` before `./start-server.ps1` to append the new password. Do not share server passwords or secrets in screenshots or logs.
